# 知识星球同步与风控处理

同步作业：`jt.zsxqSync`（「系统管理 → 定时任务」），每 3 小时执行一次，一次完成：

1. 校验 token（调用星球列表接口，失败即结束本轮，不发起任何抓取）
2. 话题同步：头部增量（补抓新帖/停机期间的帖子）+ 历史回填（游标向更早翻页）
3. 专栏增量同步（默认每 24 小时一次，同样头部增量 + 历史回填）
4. 历史帖子图片回填（每轮 `zsxq.image-backfill-batch` 条）

数据写入 `zsxq_group / zsxq_column / zsxq_topic / zsxq_comment`，游标存 `zsxq_sync_state`，运行状态存 `zsxq_job_state`。

## 一、抓取完整性

### 话题（星球主列表）

每轮分两段，互不干扰：

| 阶段 | 方向 | 上限 | 作用 |
|---|---|---|---|
| 头部增量 | 从最新往回 | 10 页（200 条） | 抓新帖；碰到上一轮已存在的帖子即停，停机多天也能补齐 |
| 历史回填 | 从游标向更早 | 5 页（100 条/星球） | 逐步覆盖存量历史 |

- 首次同步时，头部抓到的最旧时间会作为历史游标起点，避免重复抓取
- 每轮容量 ≈ 5 页 × 8 轮 = 800 条/天（另有头部增量）
- 以当前账号为例：星球共 **10,525** 条话题，按此速度约 **2 周** 追平存量；之后每轮只抓新增（约 50 条/天，远低于容量）
- 已在星球侧删除的帖子接口不再返回，无法抓取；评论接口报「主题已删除」会软删除（`visible=false`）保留历史内容

### 专栏

- 专栏列表全量同步（不设上限），专栏话题同样“头部 + 回填”
- 以当前账号为例：**6 个专栏、共 107 篇**，单轮即可全部抓完
- 专栏默认 24 小时同步一次；新发布的专栏话题会先出现在主列表，最长 24 小时后补上专栏归属

### 评论

- 新帖入库时抓取评论（最多 30 条/帖）
- 头部页里已存在的帖子，如果接口评论数比本地多，会补抓新评论（星主/成员的新回复也能同步）
- 历史帖子评论在首次入库时抓取；之后只有进入头部页的帖子才会增量刷新

## 二、只看星主

- 同步时写入：星球 `owner_id/owner`（星主），话题 `author/author_id`（作者）
- 主阅读页、专栏阅读页均有 **“只看星主”** 开关：话题按星主 ID 过滤，旧数据按昵称回退匹配
- 评论区带星主标记，并提供 **“只看星主（N）”** 开关
- 历史帖子在头部/回填翻页时会顺带补齐作者名和作者 ID，随抓取进度逐步覆盖

## 三、避免触发风控

知识星球对非官方客户端有风控（业务码 `1059`，提示「设备状态异常」或「不支持非官方工具访问」），原则是**少发请求、别发得太整齐、单轮有上限**：

| 措施 | 实现 |
|---|---|
| 复用请求 | token 校验与星球发现合并为一次 `/v2/groups`，不再额外请求 |
| 固定间隔 + 随机抖动 | 分页请求 4～6 秒、话题/评论之间 2～4 秒（固定值 + 0～2 秒随机） |
| 降低请求量 | 专栏默认 24 小时同步一次；话题每轮头部 10 页 + 回填 5 页；图片每轮默认 100 条 |
| 设备号稳定 | token 形如 `<deviceId>_<accessToken>`，请求沿用其中的设备号，避免每次都被当作新设备 |
| 避开高峰 | 作业每 3 小时一次，不并发（框架 `@DisallowConcurrentExecution`） |

## 四、触发风控后的处理

识别到 `1059`（风控）或 `40001`（限流）时：

1. **立即中止本轮**：不再发任何星球接口请求，避免越刷越严重
2. **自动冷却**：默认 240 分钟起，连续触发翻倍（240 → 480 → 720 分钟，最长 12 小时）
3. **冷却期内**：作业直接返回「知识星球风控冷却中，本轮跳过（约 N 分钟后重试）」，不发请求
4. **不污染数据**：
   - 评论接口触发风控只跳过该帖评论，不标记帖子删除
   - 图片回填触发风控不计入帖子失败次数（不会把帖子提前判死）
   - 已同步的游标/幂等键保留，冷却结束后从断点继续
5. **自动恢复**：完整跑通一轮（未触发风控）后清零连续触发计数；更换 `zsxq.token` 会立即清空冷却

任务结果与任务日志中会记录「触发知识星球风控，本轮中止；冷却 N 分钟后再试（连续第 K 次）」。

## 五、人工处置

- **想立即重试**：
  - 更换系统参数 `zsxq.token`（会自动清除冷却），或
  - 删除 `zsxq_job_state` 中 `risk_until`、`risk_strikes` 两行，例如：
    ```sql
    DELETE FROM zsxq_job_state WHERE state_key IN ('risk_until', 'risk_strikes');
    ```
- **频繁触发**：依次调小 `zsxq.image-backfill-batch`、调大 `zsxq.column-sync-interval-hours`；仍频繁出现说明 SDK 通道已被收紧，需要评估迁移到知识星球官方 `zsxq-cli`（`https://garden.zsxq.com/skill/`）。

## 六、参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `zsxq.token` | 空 | 知识星球网页 Cookie 中的 `zsxq_access_token` |
| `zsxq.image-backfill-batch` | 100 | 每轮回填的历史帖子数（1～500） |
| `zsxq.column-sync-interval-hours` | 24 | 专栏同步间隔（1～168 小时） |
| `zsxq.risk-cooldown-minutes` | 240 | 风控冷却基数（30～720 分钟），连续触发翻倍 |

> 旧版（Node）配置键为 `zsxq_token`，新版框架只认 `zsxq.token`。启动时会自动把旧键的值复制为新键；
> 若系统参数页仍为空，请重新保存一次 token。

## 七、已知限制

- 正文入库为摘要（`digest` 最多 1900 字），超长帖子只保留前 1900 字
- 评论每帖最多保存 30 条
- 已删除的帖子/评论、无权限的内容无法抓取
- 风控频繁时抓取进度会被冷却拖慢，属于预期保护行为
