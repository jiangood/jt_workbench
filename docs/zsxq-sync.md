# 知识星球同步、历史回填与风控处理

知识星球拆为两个独立 Quartz 作业（「系统管理 → 定时任务」），均使用服务器本地时间：

| 作业 key | 默认调度 | 职责 |
|---|---|---|
| `jt.zsxqSync` | 每 30 分钟（`0 0/30 * * * ?`） | 校验 Cookie、同步最新话题、到期时同步专栏增量 |
| `jt.zsxqBackfill` | 每天 08:00（`0 0 8 * * ?`） | 连续回填历史话题与专栏，补齐专栏文章完整正文和历史图片 |

> 框架自动注册只补建缺失任务，不覆盖已有配置。升级时只把 `jt.zsxqSync` 仍为旧默认值 `0 0 0/3 * * ?` 的记录迁移为每 30 分钟；手工改过的 cron 保持不动。新安装会按上表自动注册并启用两个作业。

## 一、执行流程

### 增量同步（每 30 分钟）

1. 调用星球列表接口校验 Cookie，失败即结束本轮，不发起后续抓取
2. 从最新话题往回同步，碰到上一轮已存在的帖子即停；停机期间积累的新帖会继续向前补抓
3. 专栏默认每 24 小时同步一次，只做列表与头部增量，不翻历史页
4. 首次增量同步会用头部最旧帖子的时间初始化历史游标，避免每日回填重复抓最新页

### 历史回填（每天 08:00）

1. 同样先校验 Cookie，并检查共享风控冷却状态
2. 从 `zsxq_sync_state` 的话题游标连续向更早翻页，直到空页、末页或游标无法前进
3. 拉取专栏列表，从每个专栏的游标连续回填到最早页
4. 分批调用话题详情与文章正文页，补齐专栏文章标题、摘要、作者、原文链接与完整正文 HTML
5. 分批调用话题详情，下载历史帖子图片到对象存储

回填**没有单轮请求预算或固定页数上限**。每处理完一页就保存游标；触发风控中止后，次日从断点继续。图片和专栏正文仍保留每批条数配置，避免单日请求量过大。

08:00 两个作业可能同时触发：增量作业发现回填占用锁时会跳过；若增量先运行，回填会等待增量结束后再执行，不会因为抢锁而丢掉当天回填。

数据写入 `zsxq_group / zsxq_column / zsxq_topic / zsxq_comment`，话题与专栏游标分别存 `zsxq_sync_state`、`zsxq_column.sync_cursor`，风控与专栏节流状态存 `zsxq_job_state`。

> 请求协议与模型已以源码形式内置在 `com.jt.workbench.modules.zsxq.client`，不再依赖 `zsxq-sdk`；
> 所有 ID 按字符串解析，避免 17 位话题/评论 ID 被 `Double` 舍入。

## 二、抓取完整性

### 话题（星球主列表）

| 阶段 | 方向 | 默认上限 | 作用 |
|---|---|---|---|
| 头部增量 | 从最新往回 | 2 页（40 条/星球） | 抓新帖；碰到已同步帖子即停，停机多天也能补齐 |
| 历史回填 | 从游标向更早 | 连续翻到最早页 | 完整覆盖存量历史，每页 20 条 |

- 首次增量同步时，头部抓到的最旧时间会作为历史游标起点
- 每日回填逐页保存游标，已存在话题按 `topic_id` 去重，只补作者等缺失字段
- 同一时间戳导致游标没有前进时停止，避免下轮原地打转
- 已在星球侧删除的帖子接口不再返回，无法抓取；评论接口报「主题已删除」会软删除（`visible=false`）保留历史内容

### 专栏

- 专栏列表全量同步（不设上限），专栏话题同样“头部 + 回填”
- 增量作业默认每 24 小时同步一次；每日回填也会刷新专栏列表和游标，并重置专栏节流时间
- 新发布的专栏话题会先出现在主列表，最长 24 小时后补上专栏归属
- **主信息流（知识星球页）与首页卡片只展示星球话题，归档到专栏的文章不再混入**；专栏文章统一在「知识星球专栏」里查看
- 专栏接口返回的是文章索引（`topic_id`/`create_time` 等），每日回填逐篇调用话题详情补齐标题/摘要、作者与完整正文。正文分两类：
  - 长文章（`article` 元数据）：读取 `articles.zsxq.com` 正文页；
  - 普通长贴（`type=talk`，本项目的专栏主要是这一类）：完整正文就在 `talk.text`，没有 `article` 对象。回填时把星球自定义 `<e ...>` 标记还原为普通链接、转义文本、换行转 `<br/>`，并把 `talk.images` 追加到正文末尾
- 专栏正文统一存入 `zsxq_topic.article_content`（HTML），阅读页直接展示；前端用 DOMPurify 清洗，并把星球图片改走站内代理。正文页仅允许 HTTPS 的 `articles.zsxq.com`，禁止重定向以避免 Cookie 外泄
- 正文回填按「失败次数升序 + 发帖时间升序」排队，先处理从未尝试过的旧条目，避免新内容一直占满每日批次、老专栏永远轮不到
- 专栏阅读页按发布时间正序展示，不提供搜索、星主筛选或「查看原文」入口；专栏内容均为星主发布，不再添加星主标记与强调样式

### 附件

- 话题列表/详情里的 `talk.files` 只保存**元数据**（file_id、文件名、大小、创建时间）到 `zsxq_file`，同步时不会批量下载文件内容
- 文件下载地址需要用 `file_id` 调星球 `/v2/files/{file_id}/download_url` 换取，该接口有下载量/频率监控，因此下载按需进行：
  - 阅读页点击附件时，服务端换取地址、下载到对象存储 `zsxq-file/<file_id>_<文件名>`，再以原文件名返回给浏览器；同一文件只下载一次
  - 每日回填按 `zsxq.file-backfill-batch` 批量预下载，失败 3 次后不再自动重试（仍可手动点击重试）
  - 历史帖子没有附件清单时，每日回填按 `zsxq.file-meta-backfill-batch` 调用话题详情补齐；老帖在增量/回填翻页中重新出现时也会顺带补清单，不再额外请求
- 附件与正文图片一样存对象存储，下载走站内 `admin/zsxq/file`，不依赖会过期的星球临时链接

### 评论

- 新帖入库时抓取评论（最多 30 条/帖）
- 头部页里已存在的帖子，如果接口评论数比本地多，会补抓新评论（星主/成员的新回复也能同步）
- 历史帖子评论在首次入库时抓取；之后只有进入头部页的帖子才会增量刷新

## 三、只看星主

- 同步时写入：星球 `owner_id/owner`（星主），话题 `author/author_id`（作者）
- 主阅读页提供 **“只看星主”** 开关：话题按星主 ID 过滤，旧数据按昵称回退匹配
- 主阅读页评论区带星主标记，并提供 **“只看星主（N）”** 开关
- 主阅读页把星主的话题与评论做了强化显示（淡粉底 + 左侧色条），便于扫读时一眼定位；专栏内容均为星主发布，专栏阅读页不再区分星主
- 历史帖子在头部/回填翻页时会顺带补齐作者名和作者 ID，随抓取进度逐步覆盖

## 四、避免触发风控

知识星球对非官方客户端有风控（业务码 `1059`，提示「不支持非官方工具访问」）。实测它不是固定指纹问题：网页端 48 个请求 0 命中，同一 token 从服务器直连在同样的“干净窗口”里也 0 命中；但短时间密集请求会把账号风险分推高，随后一段时间内请求会被随机拦截。原则是**按浏览器真实方式请求 + 命中后原地重试 + 少发请求/及时停手**：

| 措施 | 实现 |
|---|---|
| 浏览器同款请求 | Cookie `zsxq_access_token` + `abtest_env=product` 认证；签名 `SHA1(完整 URL + " " + 秒级时间戳 + " " + x-request-id)`；带 `X-Version / X-Aduid / Origin / Referer / Accept-Language / sec-ch-ua / sec-fetch-*` 与 Chrome UA；ID 用星球自定义 9-4-4-4-11 位格式 |
| 1059 原地重试 | 同一请求换 request-id 重试（默认 3 次，3/6/12 秒退避 + 抖动），成功后额外静默 2~3 秒；单轮累计重试上限 20 次，避免在风险窗口里靠重试放大请求量 |
| 复用请求 | Cookie 校验与星球发现合并为一次 `/v2/groups`，不再额外请求 |
| 固定间隔 + 随机抖动 | 分页请求 8～10 秒、话题/评论之间 3～5 秒（固定值 + 0～2 秒随机），可用 `zsxq.page-pause-seconds` / `zsxq.topic-pause-seconds` 调整 |
| 降低请求量 | 专栏默认 24 小时同步一次；话题增量每轮头部 2 页；图片每天回填 10 条、专栏正文每天回填 200 条（只处理待回填条目，存量补齐后不会持续产生请求）；老帖新增评论默认不补抓 |
| 分离长任务 | 增量同步每 30 分钟一次；历史回填每天 08:00 连续翻页，两者共享锁不并发 |
| 设备号稳定 | 无需手工配置：按 Cookie 派生固定的 `x-aduid`，多轮同步保持同一设备 |
| ID 精度 | 话题/评论/专栏直接按强类型 DTO 解析，所有 ID 用字符串接收，避免 64 位 `topic_id` 被 `Double` 四舍五入 |

## 五、触发风控后的处理

识别到 `1059`（风控）或 `40001`/HTTP 429（限流）时：

1. **先原地重试**：同一请求换 `x-request-id`/时间戳/签名重试（默认 3 次，2/4/8 秒退避），重试成功则本轮继续
2. **重试仍失败才中止本轮**：不再发任何星球接口请求，避免越刷越严重
3. **自动冷却**：默认 240 分钟起，连续触发翻倍（240 → 480 → 720 分钟，最长 12 小时）
4. **冷却期内**：作业直接返回「知识星球风控冷却中，本轮跳过（约 N 分钟后重试）」，不发请求
5. **不污染数据**：
   - 评论接口触发风控只跳过该帖评论，不标记帖子删除
   - 图片回填触发风控不计入帖子失败次数（不会把帖子提前判死）
   - 已同步的游标/幂等键保留，冷却结束后从断点继续
6. **自动恢复**：完整跑通一轮（未触发风控）后清零连续触发计数；更换 Cookie 会立即清空冷却

任务结果与任务日志中会记录「触发知识星球风控（code=1059，接口=…，返回=…），本轮中止；冷却 N 分钟后再试（连续第 K 次）」，可直接看出被拦的是哪个接口。

## 六、人工处置

- **想立即重试**：
  - 更换系统参数 `zsxq.cookie`（会自动清除冷却），或
  - 删除 `zsxq_job_state` 中 `risk_until`、`risk_strikes` 两行，例如：
    ```sql
    DELETE FROM zsxq_job_state WHERE state_key IN ('risk_until', 'risk_strikes');
    ```
- **频繁触发**：先确认不是重试次数设置过低（`zsxq.risk-retry-count` 默认 3 次，单次逻辑请求全失败概率约 0.2⁴≈0.16%），
  再调大 `zsxq.page-pause-seconds` / `zsxq.topic-pause-seconds`，或临时禁用 `jt.zsxqBackfill`。
  官方 Skill（`https://garden.zsxq.com/skill/`）不使用，本项目继续走网页端接口 + 浏览器同款请求 + 原地重试的方案。
- **已删除的配置**：`zsxq.request-budget`、`zsxq.backfill-pages` 已移除，数据库里的旧值不再生效，可自行清理。

## 七、参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `zsxq.cookie` | 空 | **必填**：直接粘贴浏览器 `api.zsxq.com` 请求头里的完整 Cookie（含 `zsxq_access_token`，可含 `zsxqsessionid` 等） |
| `zsxq.risk-retry-count` | 3 | 命中 1059/40001 时同一请求的原地重试次数（1～6） |
| `zsxq.risk-retry-pause-seconds` | 3 | 首次重试等待秒数（1～60），之后按 2/4/8 倍退避并叠加 0～1 秒抖动；单轮累计重试上限 20 次 |
| `zsxq.head-pages` | 2 | 增量同步头部翻页数（1～10，每页 20 条），碰到已同步帖子即提前停止 |
| `zsxq.page-pause-seconds` | 8 | 翻页间隔秒数（1～120，另加 0～2 秒抖动） |
| `zsxq.topic-pause-seconds` | 3 | 话题/评论间隔秒数（1～60，另加 0～2 秒抖动） |
| `zsxq.refresh-old-comments` | false | 是否补抓老帖新增评论（会增加请求量） |
| `zsxq.image-backfill-batch` | 10 | 每日历史回填处理的帖子数（0～500，0=关闭） |
| `zsxq.file-backfill-batch` | 20 | 每日预下载到对象存储的附件数（0～500，0=关闭；点击下载不受限） |
| `zsxq.file-meta-backfill-batch` | 10 | 每日补齐附件清单的历史帖子数（0～200，0=关闭） |
| `zsxq.column-article-backfill-batch` | 200 | 每日历史回填处理的专栏完整正文条数（0～200，0=关闭）；首次补齐存量时可保持默认一次跑完 |
| `zsxq.column-sync-interval-hours` | 24 | 增量作业的专栏同步间隔（1～168 小时）；每日回填不受此间隔限制 |
| `zsxq.risk-cooldown-minutes` | 240 | 风控冷却基数（30～720 分钟），连续触发翻倍 |

> 请在「系统参数 → 知识星球」填写 `zsxq.cookie`（仅支持 Cookie）。

## 八、已知限制

- 普通话题正文入库为摘要（`digest` 最多 1900 字），超长帖子只保留前 1900 字；专栏文章另存完整正文
- 评论每帖最多保存 30 条
- 已删除的帖子/评论、无权限的内容无法抓取
- 专栏正文按每日批次回填（默认 200 条），专栏阅读页在回填前只显示标题或摘要；正文提取规则升级后会一次性清零旧的失败计数，让误判条目重新进入队列
- 风控频繁时抓取进度会被冷却拖慢，属于预期保护行为

## 九、转为笔记

阅读页与专栏页的每条帖子都提供「转为笔记」（需要 `note:edit` 权限），可在弹窗里指定标题和笔记目录。

- 正文：专栏文章直接复用已同步的完整正文；普通帖子把 `digest` 还原成 HTML（与阅读页规则一致），并把帖子图片追加到正文
- 图片：正文里的星球官方图片会复制到框架文件库，笔记正文改用 `/file/...`；复制失败时退回站内图片代理
- 附件：话题附件先确保落入对象存储，再复制到框架文件库作为笔记附件；文件中转失败时在正文末尾保留原始下载链接
- 笔记正文为富文本（TinyMCE 编辑），保存时后端从 HTML 派生纯文本，供列表预览与搜索
- 同一话题重复转换会直接返回已有笔记（`note.source_topic_id` 去重）
- 转换会写入原文链接；「原文链接」是笔记的通用字段，手工笔记也能在编辑页填写，列表与详情页可直接跳转原文
- 转换生成的文件按私有文件保存，需要在登录态下访问；笔记编辑页删除图片/附件后由临时文件清理作业回收物理文件
