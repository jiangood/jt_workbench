# 知识星球同步与风控处理

同步作业：`jt.zsxqSync`（「系统管理 → 定时任务」），每 3 小时执行一次，一次完成：

1. 校验 token（调用星球列表接口，失败即结束本轮，不发起任何抓取）
2. 话题同步：头部增量（补抓新帖/停机期间的帖子）+ 历史回填（游标向更早翻页）
3. 专栏增量同步（默认每 24 小时一次，同样头部增量 + 历史回填）
4. 历史帖子图片回填（每轮 `zsxq.image-backfill-batch` 条）

数据写入 `zsxq_group / zsxq_column / zsxq_topic / zsxq_comment`，游标存 `zsxq_sync_state`，运行状态存 `zsxq_job_state`。

> 请求协议与模型已以源码形式内置在 `com.jt.workbench.modules.zsxq.client`，不再依赖 `zsxq-sdk`；
> 所有 ID 按字符串解析，避免 17 位话题/评论 ID 被 `Double` 舍入。

## 一、抓取完整性

### 话题（星球主列表）

每轮分两段，互不干扰：

| 阶段 | 方向 | 默认上限 | 作用 |
|---|---|---|---|
| 头部增量 | 从最新往回 | 2 页（40 条） | 抓新帖；碰到上一轮已存在的帖子即停，停机多天也能补齐 |
| 历史回填 | 从游标向更早 | 1 页（20 条/星球） | 逐步覆盖存量历史，可用 `zsxq.backfill-pages=0` 暂停 |

- 首次同步时，头部抓到的最旧时间会作为历史游标起点，避免重复抓取
- 每轮还有**请求预算**（默认 40 次星球接口调用，不含图片下载），用完即提前结束，下轮从游标继续
- 以当前账号为例：星球共 **10,525** 条话题；按默认回填速度（约 160 条/天）追平存量约需 **2 个月**。需要更快可调大 `zsxq.head-pages` / `zsxq.backfill-pages`，但请求量上升会明显增加风控概率
- 已在星球侧删除的帖子接口不再返回，无法抓取；评论接口报「主题已删除」会软删除（`visible=false`）保留历史内容

### 专栏

- 专栏列表全量同步（不设上限），专栏话题同样“头部 + 回填”
- 以当前账号为例：**6 个专栏、共 107 篇**，单轮即可全部抓完
- 专栏默认 24 小时同步一次；新发布的专栏话题会先出现在主列表，最长 24 小时后补上专栏归属

### 评论

- 新帖入库时抓取评论（最多 30 条/帖）
- 头部页里已存在的帖子，如果接口评论数比本地多，会补抓新评论（星主/成员的新回复也能同步）
- 历史帖子评论在首次入库时抓取；之后只有进入头部页的帖子才会增量刷新

## 二、只看星主

- 同步时写入：星球 `owner_id/owner`（星主），话题 `author/author_id`（作者）
- 主阅读页、专栏阅读页均有 **“只看星主”** 开关：话题按星主 ID 过滤，旧数据按昵称回退匹配
- 评论区带星主标记，并提供 **“只看星主（N）”** 开关
- 历史帖子在头部/回填翻页时会顺带补齐作者名和作者 ID，随抓取进度逐步覆盖

## 三、避免触发风控

知识星球对非官方客户端有风控（业务码 `1059`，提示「不支持非官方工具访问」）。实测它不是固定指纹问题：网页端 48 个请求 0 命中，同一 token 从服务器直连在同样的“干净窗口”里也 0 命中；但短时间密集请求会把账号风险分推高，随后一段时间内请求会被随机拦截。原则是**按浏览器真实方式请求 + 命中后原地重试 + 少发请求/及时停手**：

| 措施 | 实现 |
|---|---|
| 浏览器同款请求 | Cookie `zsxq_access_token` + `abtest_env=product` 认证；签名 `SHA1(完整 URL + " " + 秒级时间戳 + " " + x-request-id)`；带 `X-Version / X-Aduid / Origin / Referer / Accept-Language / sec-ch-ua / sec-fetch-*` 与 Chrome UA；ID 用星球自定义 9-4-4-4-11 位格式 |
| 1059 原地重试 | 同一请求换 request-id 重试（默认 3 次，3/6/12 秒退避 + 抖动），成功后额外静默 2~3 秒；单轮累计重试上限 20 次，避免在风险窗口里靠重试放大请求量；重试不额外占用请求预算 |
| 复用请求 | token 校验与星球发现合并为一次 `/v2/groups`，不再额外请求 |
| 固定间隔 + 随机抖动 | 分页请求 8～10 秒、话题/评论之间 3～5 秒（固定值 + 0～2 秒随机），可用 `zsxq.page-pause-seconds` / `zsxq.topic-pause-seconds` 调整 |
| 降低请求量 | 专栏默认 24 小时同步一次；话题每轮头部 2 页 + 回填 1 页；图片每轮 10 条；老帖新增评论默认不补抓 |
| 单轮预算 | 每轮最多 40 次星球接口请求（`zsxq.request-budget`），达到即结束，避免一次跑太久 |
| 设备号稳定 | 优先用 `zsxq.device-id`（填浏览器请求头里的 `x-aduid`，星球自定义 9-4-4-4-11 位或标准 UUID）；未配置/格式不对时按 token 派生固定值。注意 token 中 `_` 前面的部分不是 `x-aduid` |
| ID 精度 | 话题/评论/专栏直接按强类型 DTO 解析，所有 ID 用字符串接收，避免 64 位 `topic_id` 被 `Double` 四舍五入 |
| 避开高峰 | 作业每 3 小时一次，不并发（`ZsxqSyncJob` 显式标注 `@DisallowConcurrentExecution`） |

## 四、触发风控后的处理

识别到 `1059`（风控）或 `40001`/HTTP 429（限流）时：

1. **先原地重试**：同一请求换 `x-request-id`/时间戳/签名重试（默认 3 次，2/4/8 秒退避），重试成功则本轮继续，不消耗请求预算、不进入冷却
2. **重试仍失败才中止本轮**：不再发任何星球接口请求，避免越刷越严重
3. **自动冷却**：默认 240 分钟起，连续触发翻倍（240 → 480 → 720 分钟，最长 12 小时）
4. **冷却期内**：作业直接返回「知识星球风控冷却中，本轮跳过（约 N 分钟后重试）」，不发请求
5. **不污染数据**：
   - 评论接口触发风控只跳过该帖评论，不标记帖子删除
   - 图片回填触发风控不计入帖子失败次数（不会把帖子提前判死）
   - 已同步的游标/幂等键保留，冷却结束后从断点继续
6. **自动恢复**：完整跑通一轮（未触发风控）后清零连续触发计数；更换 `zsxq.token` 会立即清空冷却

任务结果与任务日志中会记录「触发知识星球风控（code=1059，接口=…，返回=…），本轮中止；冷却 N 分钟后再试（连续第 K 次）」，
可直接看出被拦的是哪个接口。请求预算用完时本轮正常结束（不进入冷却），结果提示「本轮达到请求预算上限」，下轮从游标继续。

## 五、人工处置

- **想立即重试**：
  - 更换系统参数 `zsxq.token`（会自动清除冷却），或
  - 删除 `zsxq_job_state` 中 `risk_until`、`risk_strikes` 两行，例如：
    ```sql
    DELETE FROM zsxq_job_state WHERE state_key IN ('risk_until', 'risk_strikes');
    ```
- **频繁触发**：先确认不是重试次数设置过低（`zsxq.risk-retry-count` 默认 3 次，单次逻辑请求全失败概率约 0.2⁴≈0.16%），
  再按“`zsxq.request-budget` → `zsxq.head-pages`/`zsxq.backfill-pages` → `zsxq.page-pause-seconds`”逐项收紧，
  并把 `zsxq.image-backfill-batch`、`zsxq.column-sync-interval-hours` 调到更低频率。
  官方 Skill（`https://garden.zsxq.com/skill/`）不使用，本项目继续走网页端接口 + 浏览器同款请求 + 原地重试的方案。

## 六、参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `zsxq.token` | 空 | 知识星球网页 Cookie 中的 `zsxq_access_token`；实测需整串 `<deviceId>_<accessToken>`，缺前缀会 401 |
| `zsxq.device-id` | 空 | 设备号（`x-aduid`）；填浏览器请求头里的值（星球自定义 9-4-4-4-11 位或标准 UUID），留空/格式不对时按 token 派生固定值 |
| `zsxq.app-version` | 2.100.0 | 请求头 `x-version` 使用的网页端版本，建议与当前网页端一致 |
| `zsxq.user-agent` | 空 | 可选；留空使用网页端 Chrome UA |
| `zsxq.cookie` | 空 | 可选；额外 Cookie，留空时自动发送 `zsxq_access_token=<token>`（含 token，按敏感信息保管） |
| `zsxq.risk-retry-count` | 3 | 命中 1059/40001 时同一请求的原地重试次数（1～6），不占用单轮请求预算 |
| `zsxq.risk-retry-pause-seconds` | 3 | 首次重试等待秒数（1～60），之后按 2/4/8 倍退避并叠加 0～1 秒抖动；单轮累计重试上限 20 次 |
| `zsxq.head-pages` | 2 | 每轮头部增量翻页数（1～10，每页 20 条） |
| `zsxq.backfill-pages` | 1 | 每轮历史回填翻页数（0～10，0=暂停回填） |
| `zsxq.request-budget` | 40 | 单轮星球接口请求上限（10～500，不含图片下载） |
| `zsxq.page-pause-seconds` | 8 | 翻页间隔秒数（1～120，另加 0～2 秒抖动） |
| `zsxq.topic-pause-seconds` | 3 | 话题/评论间隔秒数（1～60，另加 0～2 秒抖动） |
| `zsxq.refresh-old-comments` | false | 是否补抓老帖新增评论（会增加请求量） |
| `zsxq.image-backfill-batch` | 10 | 每轮回填的历史帖子数（0～500，0=关闭） |
| `zsxq.column-sync-interval-hours` | 24 | 专栏同步间隔（1～168 小时） |
| `zsxq.risk-cooldown-minutes` | 240 | 风控冷却基数（30～720 分钟），连续触发翻倍 |

> 旧版（Node）配置键为 `zsxq_token`，新版框架只认 `zsxq.token`。启动时会自动把旧键的值复制为新键；
> 若系统参数页仍为空，请重新保存一次 token。

## 七、已知限制

- 正文入库为摘要（`digest` 最多 1900 字），超长帖子只保留前 1900 字
- 评论每帖最多保存 30 条
- 已删除的帖子/评论、无权限的内容无法抓取
- 风控频繁时抓取进度会被冷却拖慢，属于预期保护行为
